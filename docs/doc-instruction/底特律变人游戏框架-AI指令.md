# 🎮 AI 指令：生成「底特律变人」式多主角分支叙事游戏框架

> **指令版本**: v0.1 — 理解确认版
> **目标**: 让 AI 先生成一份游戏框架设计，确认理解一致后再进入详细开发

## 一、游戏类型与核心机制

你要设计一款**交互式电影叙事游戏**，核心机制参照《底特律：变人》(Detroit: Become Human)：

| 维度 | 说明 |
|---|---|
| **视角** | 第三人称，多主角并行叙事 |
| **驱动方式** | 玩家选择驱动剧情分支，非传统数值养成 |
| **结构** | 大章节（叙事节点）→ 小章节（决策场景）→ 分支 → 后果 |
| **结局逻辑** | 无预设"好/坏"结局，结局由所有角色的路径自然汇聚而成 |

---

## 二、五主角系统

游戏共有 **5 位重要人物（主角）**，每位都有独立的叙事线：

```
         角色A ─── 大章A1 → 大章A2 → 大章A3 → ...
        /
      角色B ─── 大章B1 → 大章B2 → ...
     /
游戏开始
     \
      角色C ─── 大章C1 → 大章C2 → ...
       \
        角色D ─── ...
         角色E ─── ...
                        ↘ 所有线索汇聚 → 终章结局
```

**关键规则：**
- 每位主角的故事线在时间线上是**并行的**（同一世界、同一时间段）
- 一个角色的决策可能**跨线影响**另一个角色的后续事件
- 角色之间可能相遇、合作、对抗，也可能永远不会见面但彼此间接影响
- 玩家会交替扮演不同角色（类似底特律变人中轮流控制康纳、马库斯、卡拉）

## 三、双层章节结构（核心创新点）

这是你框架中最关键的设计，我理解为**两层决策体系**：

### 3.1 大章节（叙事层级）

```
大章节 = 一个完整的叙事单元（如"攻城战役"、"秘密谈判"、"逃亡之夜"）
```

- **决定方式**：由上一个**大章节走了哪条支线**来决定接下来进入哪个大章节
- **与数值无关**：不依赖任何属性值、好感度、资源数量
- **本质**：大章节的流转是**因果链**——因为发生了A，所以进入B；因为发生了C，所以进入D

**示例：**
```
大章「边境突围」
  ├─ 支线A：成功突围 → 下一个大章进入「盟军会合」
  └─ 支线B：突围失败被俘 → 下一个大章进入「地牢审讯」
```

### 3.2 小章节（决策层级）

```
小章节 = 大章节内的具体决策场景（如"是否开枪"、"选择信任谁"、"走哪条路"）
```

- **决定方式**：通过**数值判定**来决定小章节的结果
- **涉及数值**：角色的属性值（如：决断力、隐蔽性、口才、道德值等）
- **本质**：小章节是给玩家"操作空间"的地方，你的属性够不够、你选了什么，决定了这个小场景怎么演

**示例：**
```
大章「边境突围」内的小章节：
  小章1「贿赂守卫」→ 口才≥7 成功 / <7 触发战斗
  小章2「穿越雷区」→ 感知≥5 安全通过 / <5 受伤
  小章3「甩掉追兵」→ 敏捷≥6 逃脱 / <6 被追上
```

### 3.3 两层的关系

```
大章层级（叙事因果）
  └── 决定"接下来发生什么故事"
  └── 不依赖数值，纯叙事逻辑

小章层级（数值判定）
  └── 决定"这个故事里你怎么度过"
  └── 依赖角色属性值进行判定
  └── 小章节的累积结果 → 最终决定当前大章走哪条支线
```

**综合流程：**
```
玩家进入大章「边境突围」
  │
  ├─ 小章1: 选择贿赂/硬闯 → 数值判定 → 结果
  ├─ 小章2: 选择路线 → 数值判定 → 结果
  └─ 小章3: 关键抉择 → 数值判定 → 结果
       │
       ├─ 综合结果偏向成功 → 大章支线A: 成功突围
       └─ 综合结果偏向失败 → 大章支线B: 被捕
              │
              └─ 支线A → 连接下一个大章「盟军会合」
              └─ 支线B → 连接下一个大章「地牢审讯」
```

## 四、因果网与跨角色影响

这是底特律变人最精彩的部分——一个角色的行动会改变另一个角色的世界：

```
角色A 大章「炸毁桥梁」
  └─ 支线A: 桥被炸毁
       ├─ 角色A自己 → 无法返回东岸
       └─ 影响角色C → C的「东岸撤退」大章直接消失（因桥断了无路可退）
            └─ C被迫进入替代大章「巷战死守」
                 └─ C可能在此战死 → 后续D的大章里缺少C的支援
```

**跨角色影响的规则：**
- 一个角色的大章支线结果可以**锁定/解锁**另一个角色的大章节
- 一个角色的**死亡**会永久移除该角色的后续所有大章
- 一个角色的关键物品/信息可以传递给另一个角色（作为小章节的数值加成）

## 五、角色属性系统（仅作用于小章节）

既然大章节不依赖数值，那么数值系统只为小章节服务：

```
每个角色拥有独立的属性面板，例如：

角色A（战士型）
  ├─ 战斗 8
  ├─ 统率 6
  ├─ 口才 3
  └─ 道德 5

角色B（谋士型）
  ├─ 战斗 2
  ├─ 统率 4
  ├─ 口才 9
  └─ 道德 7
```

**属性来源：**
- **初始值**：角色背景决定
- **增长方式**：小章节中的选择 + 大章支线结果赋予的成长
- **衰减方式**：某些事件（如受重伤、精神打击）

**判定方式：**
```
小章节「说服长老」：
  ├─ 口才 ≥ 8 → "长老被你说服，给予圣物"（获得关键道具）
  ├─ 口才 4-7 → "长老犹豫不决，但未阻止你"
  └─ 口才 < 4 → "长老震怒，将你驱逐"（触发惩罚事件）
```

## 六、结局系统

结局**不是**通过分数或好感度结算，而是自然生成：

```
结局 = 五个角色最终路径的排列组合

例如：
  - 角色A 活 / 死
  - 角色B 在阵营X / 阵营Y / 死亡
  - 角色C 成功完成使命 / 失败 / 失踪
  - 角色D 成为领袖 / 叛变 / 隐居
  - 角色E 存活且关键物品到手 / 存活但失去一切 / 死亡
```

- 每个角色的终局状态由其走过的所有大章支线累积决定
- 五个角色的终局状态组合起来，就是世界的最终状态
- 不需要"好结局/坏结局"标签——每个结局都是一段完整的故事
- 底特律变人的流亡图（flowchart）式展示是理想的目标形态

## 八、技术实现提示

参考现有的 `circle-of-fate.html` 架构，新游戏应当：

- **数据层**：大章支线流转用流程图/有向图数据结构；小章用属性判定表
- **状态管理**：全局追踪 5 个角色的属性、已走过的路径、关键标记位（flag）
- **UI 层**：底特律变人式的流程图可视化（可折叠/展开的节点树）
- **存档系统**：支持回溯到任意大章节点重新选择
