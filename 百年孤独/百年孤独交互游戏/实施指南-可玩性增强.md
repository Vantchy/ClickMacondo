## 第一阶段：零风险快速胜利（改动量极小，效果极大）

### 任务 1：结算时展示"另一种可能" 🥇

**为什么排第一**：只加文案，不动任何系统逻辑。却是最强的重玩驱动力。

#### 改动清单

| 文件 | 改动类型 | 改动量 |
|------|---------|--------|
| `游戏功能/renderer.js` | 渲染逻辑：结算页新增一个展示区块 | +15 行 |
| `chapters-data.js` ~ `chapters-data-5.js` | 数据：为每个 choice 追加 `alternativeNarrative` 字段 | 约 50 条 × 30-50 字 |

#### 第一步：修改数据结构

每个 `choice` 对象新增一个可选字段 `alternativeNarrative`：

**当前结构（以第一章 round1_choice 为例）：**
```js
{
  id: 'r1_a',
  label: '拖着磁铁走进丛林',
  description: '你不回答她。你扛起磁铁，走进密林……',
  nextScene: 'round1_a_narrative',
  effects: { tags: ['执着勘探者'], fate: 2, memory: null }
}
```

**修改后：**
```js
{
  id: 'r1_a',
  label: '拖着磁铁走进丛林',
  description: '你不回答她。你扛起磁铁，走进密林……',
  nextScene: 'round1_a_narrative',
  effects: { tags: ['执着勘探者'], fate: 2, memory: null },
  alternativeNarrative: '若你当时把磁铁还给梅尔基亚德斯——乌尔苏拉会在门口站到天黑，桌上多了一碗凉掉的汤，而你的手会第一次触碰到她的手指。'
}
```

**规则**：
- 只有**被实际选择了的选项**需要结算展示 —— 展示的是"另一个没被选的选项会怎样"
- 实际做法：在结算场景中，从当前选择轮次中找出未被选择的选项，展示它们的 `alternativeNarrative`
- 如果某个 choice 没有 `alternativeNarrative`，跳过不展示

#### 第二步：修改渲染器

在 `renderer.js` 的 `renderRightPage` 函数中，结算模式的渲染代码里，在宿命值展示之后、下一步按钮之前，插入以下逻辑：

**插入位置**：`renderer.js` 第 138 行附近（记忆碎片卡片之后）

**逻辑描述**：
1. 找到当前章节中最后一次选择场景的所有选项
2. 从中筛出**未被玩家选择**且**有 `alternativeNarrative` 字段**的选项
3. 将它们渲染为一个折叠面板："📜 羊皮卷的另一页"
4. 每个展示一条 30-50 字的叙事

**渲染效果示意**：
```
┌─────────────────────────────────┐
│ 📜 羊皮卷的另一页               │
│                                 │
│ 若你当时选择「留在马孔多」——    │
│ 乌尔苏拉会在门口站到天黑，      │
│ 桌上多了一碗凉掉的汤。          │
│                                 │
│ 若你当时选择「把磁铁卖掉」——    │
│ 金币会在你的口袋里叮当作响，    │
│ 但梅尔基亚德斯会收回他本想      │
│ 给你看的那块冰。                │
└─────────────────────────────────┘
```

#### 验收标准
- [ ] 在任意章节做出选择后进入结算页，能看到"另一种可能"板块
- [ ] 文案简洁（30-50 字），文学风格与原著一致
- [ ] 如果该轮只有一个选项或没有 alternativeNarrative，板块不显示（不报错）

### 任务 2：边缘文字（Marginalia）🥈

**为什么排第二**：渲染层加一个小区域，数据层每个场景加一个可选字符串。零风险，沉浸感大幅提升。

#### 改动清单

| 文件 | 改动类型 | 改动量 |
|------|---------|--------|
| `styles.css` | 边缘文字样式 | +20 行 |
| `游戏功能/renderer.js` | 左页渲染：追加 marginalia 显示 | +8 行 |
| `chapters-data.js` ~ `chapters-data-5.js` | 数据：为部分 scene 追加 `marginalia` 字段 | 约 40 条 × 20-40 字 |

#### 第一步：修改数据结构

每个 `scene` 对象新增一个可选字段 `marginalia`：

```js
scene: {
  id: 'round1_choice',
  type: 'choice',
  // ... 现有字段 ...
  marginalia: {
    text: '此刻你手握磁铁。许多年后你会忘记磁铁的样子，但你会记得这个下午的光线。',
    position: 'bottom-right',  // 位置：'top-left' | 'bottom-right' | 'side-note'
    style: 'whisper'           // 风格：'whisper'（低语）| 'warning'（警告）| 'echo'（回响）
  }
}
```

**边缘文字类型与风格对应**：
- `whisper`：灰色潦草字迹 —— 前人的情感共鸣
- `warning`：暗红色下划线 —— 命运的暗示
- `echo`：淡金色斜体 —— 梅尔基亚德斯的旁注

#### 第二步：修改渲染器

在 `renderer.js` 的 `renderLeftPage` 函数中，正文段落渲染完毕后，追加边缘文字：

**插入位置**：`leftPage.innerHTML = html;` 之前

**逻辑**：如果 `scene.marginalia` 存在，在 HTML 末尾追加一个 `<div class="marginalia marginalia-${style}">`

#### 第三步：添加 CSS 样式

```css

  font-size: 0.68rem;

  opacity: 0.6;
  pointer-events: none;
  user-select: none;
}
.marginalia-whisper {
  color: #8a8a7a;
  font-style: italic;
  right: -190px;
  bottom: 40px;
  border-left: 1px solid rgba(138,138,122,0.3);
  padding-left: 10px;
}
.marginalia-warning {
  color: #a04030;
  right: -190px;
  top: 60px;
  border-left: 1px solid rgba(160,64,48,0.3);
  padding-left: 10px;
}
.marginalia-echo {
  color: #b88a3e;
  right: -190px;
```

#### 边缘文字内容示例

|------|------|---------|------|
| 第一章 | 磁铁选择 | "此刻你手握磁铁。多年后你会忘记磁铁的样子，但你会记得这个下午的光线。" | whisper |

#### 验收标准
- [ ] 至少 30 个场景拥有边缘文字
- [ ] 三种风格视觉上有明显区分
- [ ] 边缘文字不遮挡正文，不干扰阅读
- [ ] 在移动端（窄屏）上自动隐藏

### 任务 4：事件倒计时 / 命运预告

**为什么排第四**：纯文案追加，零代码改动。但效果极强——创造"我知道要发生什么但无法阻止"的宿命感。

#### 改动清单

| 文件 | 改动类型 | 改动量 |
|------|---------|--------|
| `chapters-data.js` ~ `chapters-data-5.js` | 数据：章节结算的 summary 追加预告文案 | 约 15 条 |

#### 实施方式

在关键章节的结算 `summary` 字段中，追加一段"命运预告"。这不是新系统——只是文案策略。

**示例**：

| 章节结算 | 追加的预告文案 |
|---------|-------------|
| 第一章结算 | "命运预告：失眠症正在河对岸的印第安村落里蔓延。它还有两章就会抵达马孔多。届时，你将忘记所有事物的名字。" |
| 第四章结算 | "命运预告：皮埃特罗的钢琴声还会响很久——但丽贝卡和何塞·阿尔卡蒂奥已经在彼此的目光里看见了另一种未来。婚礼永远不会办成。你知道这一点。阿玛兰妲也知道。" |
| 第八章结算 | "命运预告：美人儿蕾梅黛丝不属于这个世界。风已经在晾床单的时候试探过她的重量。你还有最多两章——在风把她带走之前，多看她一眼。" |
| 第九章结算 | "命运预告：香蕉公司的人已经到了。他们说话的方式让你想起吉卜赛人——但吉卜赛人只拿走你的好奇，他们会拿走一切。包括三千条人命。" |
| 第十一章结算 | "命运预告：大雨将在本章结束时停止。但洪水冲走的不只是泥土——还有布恩迪亚家最后一点辉煌。从下一章开始，你将亲眼看着一切腐烂。" |

**为什么有效**：
- 玩家提前知道会发生什么——但不知道以什么方式、在什么时刻
- 这种"提前预知"就是宿命感的本质
- 不需要写新系统——就是文案

#### 验收标准
- [ ] 至少 10 个章节结算包含命运预告
- [ ] 预告不透露具体细节，保留悬念
- [ ] 预告的语言风格与原著"多年以后"的回望叙事一致

## 第二阶段：核心玩法增强（中等改动，高收益）

### 任务 5：记忆碎片 → 可用道具

**核心思路**：已有的 memory 系统只用于"收集→查看"。改造为"收集→解锁后续选项"。

#### 改动清单

| 文件 | 改动类型 | 改动量 |
|------|---------|--------|
| `游戏功能/chapter-registry.js` | memoryRegistry 追加 unlock 字段 | +5 行 |
| `游戏功能/game-engine.js` | selectChoice 增加碎片检查逻辑 | +15 行 |
| `游戏功能/renderer.js` | 选项渲染时显示"🔑 线索解锁"标记 | +10 行 |
| `chapters-data-1.js` ~ `chapters-data-5.js` | 为部分 choice 追加 `requiredMemory` 字段 | 约 8 条 |

#### 第一步：扩展记忆碎片数据结构

当前记忆碎片：
```js
memoryRegistry = {
  'mem_magnets': {
    id: 'mem_magnets',
    title: '磁铁与勘探',
    description: '你拖着磁铁走进丛林……',
    chapter: 1
  }
}
```

扩展后追加 `unlockHint` 和 `unlocksIn`：
```js
memoryRegistry = {
  'mem_magnets': {
    id: 'mem_magnets',
    title: '磁铁与勘探',
    description: '你拖着磁铁走进丛林……',
    chapter: 1,
    unlockHint: '在第五章战争场景中，磁铁将帮助你感知到埋在地下的武器',
    unlocksIn: ['chapter5']  // 在哪些章节触发额外选项
  }
}
```

#### 第二步：选项的条件显示

为 choice 新增可选字段 `requiredMemory`：
```js
{
  id: 'r5_secret',
  label: '用磁铁感应敌军武器的位置',          // 🔑 线索解锁选项
  description: '你蹲下身子，把磁铁贴近地面——它在震动……',
  nextScene: 'r5_secret_narrative',
  effects: { tags: ['磁铁战术'], fate: 3, memory: null },
  requiredMemory: 'mem_magnets',               // 需要持有此碎片才能看到此选项
  isSecretOption: true                          // 标记为隐藏选项，渲染时加特殊样式
}
```

#### 第三步：引擎逻辑修改

在 `game-engine.js` 的 `selectChoice` 被调用前，`renderRightPage` 渲染选项列表时需要先做过滤：

**逻辑**：遍历 `scene.choices`，筛掉 `requiredMemory` 不满足的选项。满足条件 = `GameState.memories.includes(choice.requiredMemory)`

#### 第四步：渲染提示

条件解锁的选项在渲染时追加一个金色小标记：
```
🔑 线索解锁：拖着磁铁走进丛林  →  用磁铁感应敌军武器的位置
```

#### 碎片→选项连锁设计表

| 碎片 | 来源章节 | 解锁章节 | 解锁的隐藏选项 |
|------|---------|---------|-------------|
| 磁铁与勘探 | 第一章 | 第五章 | "用磁铁感应敌军武器位置" |
| 乌尔苏拉的草药方 | 第二章 | 第八章 | "在丽贝卡吃泥土时递给她药汤" |
| 皮埃特罗的钢琴曲 | 第四章 | 第六章 | "在行刑队面前哼那首钢琴曲——阿玛兰妲会听见" |
| 三千人的名字 | 第十章 | 终章 | "在梅尔基亚德斯面前说出那三千个名字" |
| 丽贝卡的骨灰盒 | 第三章 | 第十六章 | "把骨灰盒放在她门口——她会在深夜打开门" |

#### 验收标准
- [ ] 至少 5 条记忆碎片拥有解锁效果
- [ ] 未持有碎片时隐藏选项不可见
- [ ] 持有时选项带特殊标记（金色边框或🔑图标）
- [ ] 选项渲染逻辑不影响普通选项

### 任务 6：道德张力选择重写

**核心思路**：重写关键章节的选项，让每个重要选择都变成"两个好东西的竞争"或"两个坏东西的取舍"。同时为这些选择追加情感结算文案。

#### 改动清单

| 文件 | 改动类型 | 改动量 |
|------|---------|--------|
| `chapters-data-1.js` ~ `chapters-data-5.js` | 重写约 10 个关键选择的 label/description + 追加 `emotionalCost` 字段 | 纯文案 |
| `游戏功能/renderer.js` | 结算时渲染 emotionalCost | +10 行 |

#### 重写的选择设计

**第一章 · 磁铁选择**（已在数据中存在，重写文案增加张力）：

当前选项是"信息偏好型"——三个选项各有各的趣味，但没有"代价"。

改进方向：让每个选项的**代价**在 description 中明确写出来。

```
选项 A：「拖着磁铁走进丛林」
  → 获得：发现黄金的（渺茫）可能
  → 失去：乌尔苏拉会在那个下午独自站在门口，她从此不再等你回家吃饭

选项 B：「把磁铁还给梅尔基亚德斯」  
  → 获得：乌尔苏拉的感激——她会握住你的手
  → 失去：你永远放弃了"磁铁能挖出黄金"这个想法。某种狂热从你眼睛里熄灭了。

选项 C：「把磁铁卖掉换回骡子和山羊」
  → 获得：物质安稳，家庭温饱
  → 失去：梅尔基亚德斯收回了他本想给你看的那块冰。你永远不会知道冰是什么。
```

**判断逻辑**：
```js
// 伪代码
```

  > 上面只有一行字。不是梅尔基亚德斯的字迹。
  > 是你自己写的。
  > "至少这一行，是我写的。"

**结局 C：宿命旁观者**（新增）：

  > 百年孤独——你读完了全部，但从未真正属于这间屋子。

#### 第三步：角色生死 — 以乌尔苏拉为例

**条件链设计**：
- "乌尔苏拉是否失明" = 在第一章至第十一章中，选择带有 `caresForUrsula` 标记的选项次数 ≥ 4
- 如果 ≥ 4：第十二章乌尔苏拉场景改为"未失明变体"——她仍能看见，仍在缝补，但与世界的连接方式不同
- 如果 < 4：按原著走向（失明）

**实现方式**：
1. 在相关 choice 的 effects 中追加 `characterFlag: { 'ursula_cared': true }`（可选字段，不破坏现有结构）
2. 在 game-state.js 中新增 `characterFlags` 存储：`characterFlags: {}`
3. 第十二章入口处检查 `characterFlags.ursula_cared` 计数，决定使用哪套场景

## 附录 C：写文案时的风格指南

以下句子摘自原著，作为所有新增文案的语调参考：

> "多年以后，面对行刑队，奥雷里亚诺·布恩迪亚上校将会回想起父亲带他去见识冰块的那个遥远的下午。"

**关键特征**：
1. **时间折叠**：现在、过去、未来在同一句话中共存
2. **具体感官细节**：冰块的冷、磁铁的嗡鸣、泥土的气味
3. **沉重的简洁**：句子不长，但每个词都承载着命运
4. **不说教**：从不直接说"这是悲伤的"——只描述事实，让悲伤自己渗出
5. **名字的重量**：全名是有意义的——"奥雷里亚诺·布恩迪亚上校"不能简称为"上校"

**写"另一种可能"文案时的模板**：
> "若你当时选择了 [另一选项] —— [一个具体的感官画面]。[一个细微但不可逆的后果]。"

**示例**：
- ✅ "若你当时把磁铁还给梅尔基亚德斯——乌尔苏拉会在门口站到天黑，桌上多了一碗凉掉的汤。而你会在那天晚上第一次注意到她手上的茧。"
- ❌ "选择还磁铁会让你和乌尔苏拉的关系更好。"（太直白、太游戏化）
